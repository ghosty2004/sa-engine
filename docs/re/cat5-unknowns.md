# CAT-5: classification of the 9,454 unknown game-.text procedures

> Update 2026-11-05 (CAT-12, `cat9-12-pipeline.md`): the catalogue now also holds Ghidra-missed vtable
> slots and CAT-7 call targets, so the classified set is 9,851 rows (game 2,847, RW 340, CRT 509,
> QuickTime 36; the other classes unchanged). Vtable slots are named from validated header layouts
> (`tools/catalog/vtables.py`, `Declaring::Slot`) before falling back to `Class::vfunc_N`.

Generated by `tools/catalog/classify_unknowns.py` → `catalog/classification.csv`
(`address, class, subsystem, name, evidence`), consumed by `tools/catalog/subsystems.py`.
Pipeline: `build_catalog.py` → `merge_ghidra.py` → `classify_unknowns.py` → `subsystems.py`.
The script is deterministic and idempotent: it gives the same output on a fresh `merge_ghidra.py`
output and on a `procedures.csv` that `subsystems.py` has already rewritten (checked).

## Method

Everything is computed from the exe bytes plus the catalogue, with no per-function hand labels:

- **Xref index.** capstone linear sweep of every procedure span `[entry, next entry)` in game `.text`,
  `_rwcseg`, `.HOODLUM` and `_TEXT_HA`. It records `call`/`jmp` targets, absolute imm/disp operands
  (strings, imports, code addresses), aligned code pointers in `.rdata`/`.data`/`_rwdseg` (vtables,
  callback tables), and aligned code pointers inside `.text` (switch jump tables).
- **Known anchors.** gta-reversed hooks (`functions.csv`) and callees (`callees.csv`, with the source
  file of the first call site), Ghidra FID names (MSVC library hashes) from `procedures.csv`, plugin-sdk
  names (`re/plugin-sdk`, a shallow clone at `15f15b6`: meta files, `addrof` tables, raw-cast bodies),
  and gta-reversed `RH_ScopedVirtualClass(class, vtable, n)` vtables.
- **REA/Ghidra checks** on the snapshot: the D3DX preprocessor's predefined macros (`0x76d37e` defines
  `DIRECT3D`, `D3DX`, `DIRECT3D_VERSION`=0x900 and `D3DX_VERSION`=0x900) and the QuickTime loader
  (`0x819520`: `LoadLibrary("QuickTime.qts")`, then `GetProcAddress` of `_CallComponentFunctionWithStorage`,
  `_CallComponent` and `theQuickTimeDispatcher`).

The rules run in this order. The first rule that matches a procedure wins.

1. **EH funclets.** The script finds every `mov eax, FuncInfo; jmp ___CxxFrameHandler` stub, where the
   handler is the one FID-named `___CxxFrameHandler` at 0x8215a0. It found 1,727 stubs (0x837186–0x848f06).
   Every FuncInfo has magic 0x19930520. Each unwind-map `action` and each catch-handler address is a
   funclet. That gives 3,547 unwind actions (all of them Ghidra procedures) and 15 catch handlers (9 of them
   Ghidra procedures, including 8 `Catch@` in the game part of `.text` and 1 in D3DX).
2. **Linker thunks.** `jmp [IAT]` import thunks (vorbisfile, WS2_32, KERNEL32, and the delay-loaded
   D3D9/DINPUT8/DSOUND/DDRAW thunks) and delay-load `__imp_load_*` stubs (`mov eax, __imp_X; jmp
   __tailMerge`).
3. **CRT.** The MSVC runtime is linked last. Its block runs from FID `ULI::Unlink` (delayhlp.cpp) at
   0x820ce6 to the first EH funclet at 0x837170. It holds 242 FID matches and no gta-reversed hook (the
   script asserts this). The game calls into it, for example `_rand`, `_malloc` and `operator_new`. FID
   names outside this block are not trusted. For example, `_fclose` at 0x4ab260 stays game code.
4. **Third-party blocks.** Each block lies between known RenderWare functions. The script asserts that each
   block has identifying strings and no gta-reversed or plugin-sdk function. Per-function evidence comes in
   three strengths: (a) the function references the library's strings; (b) it is in a call-graph or vtable
   component with such a function; (c) link order only (inside the block, no link to a string-bearing
   function, often uncalled library code or COM vtable members).
5. **SecuROM fragments and mis-splits.** See the protection section below.
6. **RenderWare.** The RenderWare span runs from the first RenderWare thunk after the last game
   function (0x748f20) to the CRT block, minus the third-party blocks. The script asserts that no
   non-RenderWare gta-reversed function lies inside it. The only exception is `WindowedMode.cpp`, whose hooks
   are RenderWare D3D9-driver functions. `_rwcseg` (0x857000) is RenderWare's assembly segment, and its code
   uses `_rwdseg` data.
7. **Game.** Everything else. The name comes from plugin-sdk or from a gta-reversed vtable slot
   (`Class::vfunc_N`). The subsystem comes from that name, or else from callers: every caller must be in
   the same subsystem, iterated 4 times. Otherwise the subsystem is `UNK-game`.

## Evidence per class

- **eh-funclet**: FuncInfo tables (see rule 1). The evidence column names the FuncInfo, the state index
  and the stub address.
- **crt**: 242 rows carry a Ghidra FID match (MSVC library hash). The other 266 rows carry the block
  bounds and how many runtime functions they call. Delay-load helper code (`ULI`,
  `__HrLoadAllImportsForDll`) is counted here.
- **thirdparty:d3dx9**, block 0x7652ae–0x7c45e0: a statically linked **D3DX9** (pre-DLL SDK). It contains
  the `D3DX9 Shader Assembler` and `D3DX9 Shader Compiler` strings, the HLSL preprocessor (`#pragma
  pack_matrix`, `D3DX_VERSION`) and shader-assembler messages. It reads `DisableD3DXPSGP` under
  `Software\Microsoft\Direct3D` (the PSGP math dispatch). Its functions are not 16-byte aligned (MS
  library build), unlike RW and game code. RenderWare calls into it (for example 0x7646e0/0x764730 →
  0x7672e1/0x7675ee/0x7676c7, and 0x75ee60 → 0x7652ae), so it is used by the RW D3D9 pipelines.
  Evidence strength: 13 string, 838 component, 98 link-order only.
- **thirdparty:libpng-1.0.12+zlib-1.1.3**, block 0x7cfe00–0x7eb5c0: it contains `libpng version 1.0.12 -
  June 8, 2001`, the chunk/IHDR messages and the zlib 1.1.3 inflate/inftrees messages. It sits right after
  RenderWare's `rtpng` (0x7cf600) and before `rtquat`, so RtPNG links it. Functions with zlib-only messages
  are tagged `zlib` in the evidence. The block is not otherwise split between libpng and zlib. Evidence:
  52 string, 141 component, 1 link-order only.
- **thirdparty:quicktime-qtml**, block 0x818430–0x81e406: QuickTime-for-Windows client glue (QTML). Each
  stub is `mov eax, selector; jmp [theQuickTimeDispatcher]`, and the loader is shown above. The callers
  are game audio code at 0x4e77c0–0x4e7cb0, the MP3/user-track path. This library is
  **game-relevant**: user-track MP3 decoding depends on it, so the Rust side needs its own decoder there.
  Evidence: 3 string, 2 component, 29 dispatcher stubs (called from game audio code, not from each other,
  so their evidence column says link order; the stub shape itself identifies them).
- **protection**: SecuROM code-displacement. Instructions inside game functions were replaced by
  `jmp fragment`. The fragment runs the displaced instructions, often obfuscated with `pushfd/popfd` and
  key reads from `.HOODLUM`/second `.data`, and jumps back into the host.
  - 399: fragment area 0x401000–0x403e20 (before the first game function), only jumped to.
  - 18: SecuROM runtime in that area, referenced only from inside it (`pushal` wrappers, calls through
    `_TEXT_HA` pointers, stubs into `.HOODLUM`).
  - 292: fragments in the dead space of other functions (mostly after `.HOODLUM` stubs), which jump back
    into the span of the host that jumps to them.
  - 32: displaced epilogues in the dead span of a `.HOODLUM` stub.
- **mis-split** (Ghidra procedures that are not functions):
  - 627: SecuROM re-entry points. Ghidra starts a procedure at the jump-back target inside the host. The
    address is mid-body (not after padding) and is only jumped to from protection code. Example: 0x405175
    inside `CIplStore::LoadIpls`.
  - 5: switch-case labels (`switchD_…::caseD_…`).
  - 21: in-span pieces or tails of a known function.
- **RW**: 286 call-graph components that contain gta-reversed RenderWare functions; 4 plugin-sdk RW names
  (`_rwStreamReadChunkHeader`, `RwEngineGetVideoModeInfo`, `_rwD3D9RenderStateVertexAlphaEnable`,
  `_rwD3D9RenderStateIsVertexAlphaEnable`); 8 in `_rwcseg`; 10 link order only (0x7cb6a0, 0x7cb828,
  0x7cb8b0, 0x7f5f20, 0x7fd810, 0x803740, 0x80ce10, 0x80d100, 0x80d210, 0x80d680).

## What remains: real game code (2,481)

- Named: 648. Of these, 437 are vtable slots of gta-reversed classes and 211 have plugin-sdk names. One
  of them, 0x4cbe20, is named `_rwD3D9CheckValidCameraTextureFormat` by plugin-sdk but lies in the game
  part of `.text`; it is kept as game with subsystem RW.
- Subsystem known: 1,015. The sources are name or vtable (516) and unanimous callers (499; this is
  weaker evidence and is marked in the evidence column). The remaining 1,466 are `UNK-game`: real
  functions whose subsystem is not established.
- 106 are game-.text stubs to relocated `.HOODLUM` bodies (real game functions, hook the stub).
- 198 have no static reference (dead code, or reached through a computed pointer). They are still
  counted as game code.

## Not proven / caveats

- 98 D3DX, 29 QuickTime stubs, 1 libpng and 10 RW rows rest on link order alone. They are flagged in the evidence column.
- The caller-based subsystem is a bookkeeping assignment, not a behavioural claim.
- The libpng/zlib split is not complete inside the shared block.
- Procedure spans are `[entry, next entry)`. Ghidra function bodies were not in the evidence bundle, so
  a few xrefs may be attributed to a neighbouring procedure.
