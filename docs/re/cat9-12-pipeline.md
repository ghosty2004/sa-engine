## CAT-12: closing the catalogue

`merge_ghidra.py` now adds every code address that the evidence names as a function entry and
Ghidra's auto-analysis missed. Each row's `ghidra_name` says `(missed by ghidra: <rule>)`:

| rule | rows | evidence |
|---|---:|---|
| hook | 1,894 | gta-reversed hook address with status `ok` or `stub-to-.HOODLUM`. The second status is new; 3 of the 153 were such stubs (0x411330, 0x41c050, 0x4588b0) |
| callee | 416 | gta-reversed `plugin::Call` / raw-thunk target with status `ok`. Before, these were only kept when Ghidra had a procedure there. None lies inside another function's Ghidra body |
| vtable | 351 | slot of a gta-reversed `RH_ScopedVirtualClass` vtable that points into game code |
| cat7-call | 46 | direct call target found by CAT-7 in a catalogued body. They are listed with their callers in `catalog/extra-code-addresses.csv`, a tracked input that `callgraph.py gaps` appends to |

`callgraph.py gaps` is a fixpoint step. When CAT-7 finds a call or tail-call target outside the
catalogue, it appends the target and exits with 3, and `run_all.sh` reruns from `build_catalog`.
Any other gap (a vtable slot, or `.HOODLUM`/protection code that is not a SecuROM thunk) exits
with 4, which means a rule is missing. From the committed state, one pass is enough.
Bootstrapping took 3 passes (41, then 5, then 0 targets): the added callees made more bodies
visible.

Calls into SecuROM code are now classified as `excluded:protection-thunk` (`callgraph.py
securom_thunk`). There are 49 targets and 75 sites. A target qualifies if it lies in the protection
`.text` (0xCB1000–0x1301000), or if it is `.HOODLUM` code that rewrites its own return address
(`add dword ptr [esp(+k)], imm` before its first ret/jmp). All 47 `.HOODLUM` targets have the
second shape: they decode a key into a register and return past junk bytes behind the call site.
**Caveat for CAT-7 bodies:** the bytes right after such a call are junk and are not executed. The
linear decode of the caller can therefore misread a few instructions there. This was not changed.

Result: `cat7-stats.json` reports `noncatalogue_targets` = 0. That means 0 call, tail-call or
vtable targets lie outside the catalogue, `.HOODLUM` included. Of the original 153 targets: 3 are
hooks (named), 9 are gta-reversed callees (unnamed, `CALLED-ONLY`; 2 of them are also vtable slots),
112 are named game rows (vtable slots with a validated slot name, or a plugin-sdk name), 18 are
vtable slots of unvalidated classes (`Class::vfunc_N`), 8 are unnamed game call targets, 2 are
QuickTime glue, and 0x82263a `_purecall` is CRT. All 153 are now catalogue rows.

### Vtable slot names (`tools/catalog/vtables.py`)

gta-reversed only hooks the out-of-line virtuals. Inline header virtuals (`GetEventType`,
`GetLifeTime`, …) used to be catalogued as `C::vfunc_N`. `vtables.py` rebuilds each class's
slot layout from the header declarations:

- the primary base's layout, with overrides kept in their slot;
- then the class's new virtuals, in declaration order;
- the destructor takes one slot.

A layout is used only if all of the following hold:

1. Its slot count equals the `n` given in `RH_ScopedVirtualClass`.
2. Every `RH_ScopedVMTInstall` hook of the class, and every hook of an ancestor whose slot is not
   overridden, sits in the slot the layout gives it.
3. Every inline `{ return <int>; }` body matches the original slot code (`mov eax, imm; ret`,
   `xor eax, eax; ret`, `mov al, imm; ret`).
4. No class in the chain declares overloaded virtuals. MSVC reverses overload order, so the
   layout cannot be proven in that case.
5. Every ancestor is parsed.

328 of 379 vtables pass, covering 3,487 slots. The 51 that fail mostly hit rule 4: `CEntity::Add`,
which affects the whole entity/vehicle/ped tree, and `CBaseModelInfo::CreateInstance`. The rest
have slot-count or hook mismatches, which point to incomplete gta-reversed headers. The name is
`DeclaringClass::Slot`, where the declaring class is the last class in the chain that declares the
slot. An inherited body is therefore named after its base, for example 0x681f20 =
`CTaskComplexPartner::CreateFirstSubTask`, which is shared by `...PartnerChat` and `...PartnerShove`.
Bodies that identical-code folding shares across different declaring classes keep the most-base
class and say so in the evidence. 676 classified rows carry a validated slot name. 111 rows are
still `vfunc_N`.

## CAT-9: `.HOODLUM` double count

`merge_ghidra.py` gives a `.HOODLUM` procedure the state `stub-body` when it is the body of a
game-.text `jmp` stub. Its name is the stub's name. It is not counted as a function. The function
row is the stub address, and its extent (CAT-7 `extents.csv`) is the 5-byte stub plus the body
(`hoodlum_body` column).

There are 497 stubs and 497 distinct bodies; no body is shared by two stubs. 492 of the bodies are
Ghidra procedures, which is why the `stub-body` column shows 492. 379 of the stubs are gta-reversed
hooks. `summary.md` now has a `functions` column and a separate `stub-body` column.
`subsystems.py` appends a reconciliation section (asserted in code):

- `procedures.csv` rows = `subsystems.md` total = `summary.md` game-text + rw-cseg functions =
  `state.csv` rows = **19,425**.
- Distinct hook addresses: 8,632. 8,630 are in the catalogue (7,900 reversed, 730 not). The other
  2 are 0x8d0aa8 (in `.data`) and 0xdeadbeef (a placeholder).
- The old summary counted 357+17 `.HOODLUM` bodies a second time as gr-reversed/gr-unreversed.

Note: CLAUDE.md's "501 stubs" came from `hoodlum_xrefs.py` (jmp sites). The catalogue has 497 stub
procedures.

## CAT-10 part 2: the original's handler per opcode

`CRunningScript::ProcessOneCommand` (0x469EB0) does `mov edx, [edx*4 + 0x8A6168]; call edx` with
`opcode / 100` as the index (`imul 0x51EB851F`). The table holds 27 `ProcessCommandsXToY` functions,
followed by the word 0xFFFF. `script_commands.py` decodes each switch:

1. the load of the opcode argument, checked against the first stack argument with esp tracking
   (push/pop and the SEH prologue);
2. the bias (`add` / `lea`) and the bound (`cmp r, n; ja default`);
3. MSVC's optional byte index table, used in ranges 200–1399;
4. the jump table.

Ranges with holes:

| range | cases |
|---|---|
| 100 | 100–196 |
| 200 | 214–297 |
| 300 | 311–399 |
| 600 | 659–697 |
| 700 | 703–798 |
| 1100 | 1101–1199 |
| 1300 | 1301–1397 |
| 1400 | 1403–1499 |
| 1500 | 1500–1593 |
| 1600 | 1602–1699 |
| 2600 | 2600–2638 |

Each switch's `default` returns -1 (`or al, 0xff`). In range 2500 the epilogue was displaced by
SecuROM (`jmp 0x403a66`).

New columns in `catalog/script-commands.csv`:

- `orig_handler`: the case address;
- `orig_range_fn`;
- `orig_dispatch`: `case`, `default` (no handler in the PC exe) or `no-range-function` (≥ 2700, the
  CLEO/NOTSA opcodes);
- `orig_case_shared`: the number of opcodes that share the case block. Up to 30 share one, for
  example the common "do nothing" blocks of the `nop` commands.

gta-reversed status compared with the original dispatch:

| gta-reversed | case | default | no range fn |
|---|---:|---:|---:|
| handler | 741 | 15 | 14 |
| nop | 281 | 0 | 0 |
| unimplemented | 70 | 643 | 0 |
| unsupported | 0 | 13 | 0 |
| unregistered | 878 | 0 | 171 |

All 13 `unsupported` opcodes and 643 of the 713 `unimplemented` ones fall to the default, which
fits the gta-reversed labels. 70 `unimplemented` opcodes do have a case in the exe, so gta-reversed
has not ported them yet. 15 `handler` opcodes are absent from the PC switch: `RETURN_TRUE/FALSE`
(0xC5/0xC6), `PRINT_WITH_*_NUMBERS*` variants, `IS_FIRST/SECOND_CAR_COLOUR`, `SET_CHAR_ARMOUR` and
`FINISHED_WITH_XBOX_PLAYER2`. In the original these reach the default and return -1, so
gta-reversed's handlers for them are not 1:1. The 878 `unregistered` opcodes with a case are the
ones gta-reversed still runs through its legacy switch code.

## CAT-11: state file and progress

`catalog/state.csv` has the columns `address, name, subsystem, state, source, evidence, updated`.
`progress.py merge` derives the state of each function:

| catalogue row | state | source |
|---|---|---|
| excluded | `excluded` | (evidence = class) |
| gr-reversed | `specified` | gta-reversed |
| named gr-unreversed / gr-called-only / unknown | `specified` | REA |
| otherwise | `unknown` | |

The merge never overwrites a state above `specified`. A row whose address leaves the catalogue is
kept as an orphan. `updated` changes only when the state, source or evidence of a row changes
(`$SA_STATE_DATE`), so reruns are byte-stable. State changes are recorded with
`progress.py set ADDRESS STATE EVIDENCE`.

Set on 2026-11-05 as `implemented` (no recorded oracle, so not L1/L2):

- 0x53CB50 `CGeneral::LimitRadianAngle`
- 0x441390 `CGameLogic::IsCoopGameGoingOn`
- 0x561B10 `CTimer::Update`, a passthrough hook with no Rust logic, marked as briefed

`progress.py report` writes `catalog/progress.md`: counts per subsystem and state, and F1 = the
share of non-excluded functions at L2 or L3. Today that is 0 / 12,761.
