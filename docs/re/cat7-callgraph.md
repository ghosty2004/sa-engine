# CAT-7: call graph, global read/write sets, extents, port order

> Update 2026-11-05 (CAT-12): the catalogue grew (19,425 functions, 12,761 live). Current totals are in
> `catalog/raw/cat7-stats.json` (e.g. 32,128 call edges, 5,159 unresolved indirect sites, 4,473 leaves).
> The numbers below are from the first CAT-7 run on 11,945 live functions; the method is unchanged.
> The Ghidra dump log is now `target/ghidra/dump.log`.

Generated by `tools/catalog/callgraph.py` (+ `tools/catalog/ghidra/DumpCat7.java`) for the 11,945
non-excluded procedures of `catalog/procedures.csv` (states `gr-reversed` 7,894, `gr-unreversed` 730,
`gr-called-only` 528, `unknown` 2,793).

## Regenerate

```sh
.venv/bin/python -I tools/catalog/callgraph.py ghidra   # ~3 min first time (import + auto-analysis into
                                                         # target/ghidra), then ~15 s (-readOnly dump)
.venv/bin/python -I tools/catalog/callgraph.py build    # ~30 s, writes the CSVs below
.venv/bin/python -I tools/catalog/callgraph.py spotcheck 10 7   # verification against gta-reversed
```

Inputs: the exe, `catalog/procedures.csv` + `classification.csv` (CAT-4/5), `functions.csv`,
`re/gta-reversed`, `re/plugin-sdk`. Ghidra 12.1.2 headless (`/opt/ghidra`), project in `target/ghidra`.
The dump runs with `-readOnly`, so every run starts from the same analysed state.

Reproducibility (checked 2026-11-05): `ghidra` + `build` twice on the same project, and once more after
deleting `target/ghidra` (fresh import + auto-analysis), gave byte-identical `extents.csv`,
`callgraph.csv`, `rwsets.csv`, `indirect-calls.csv`, `port-order.csv`, `raw/ghidra/functions.jsonl` and
`raw/cat7-stats.json` (sha256 compared).

## Method

### 1. Extents (Ghidra)
Fresh headless import + default auto-analysis of the exe, then `DumpCat7.java`:

1. Remove the Function objects at the 1,394 CAT-5 `excluded:mis-split` / `excluded:protection`
   procedures (1,568 incl. ones re-created later), and drop the flow override on the 1,321 jumps into
   them. Host bodies then flow through SecuROM displaced-code fragments and past re-entry points, so
   displaced instructions (and their calls/globals) count for the host.
2. Ghidra's analysis flagged `_free` (0x82413f) and its three thunks (0x72f430, 0x8213ae = operator
   delete, 0x8214bd) non-returning. That cut 800 callers right after the call. The flag is cleared on
   those (kept on `_abort`, `__exit`, `_CxxThrowException`, `_longjmp`) and the call sites' fall-through
   restored.
3. Create a function at every catalogue address and every `.HOODLUM` body reached from a game stub:
   2,044 created, 0 failures. 1,888 of these are the gta-reversed hook targets Ghidra missed. Two hook
   entries (0x427740, 0x6cffd0) had been typed as data by auto-analysis and were cleared first.
4. 174 functions whose first instruction is `jmp fragment` had been turned into thunks; they are
   un-thunked.
5. Heal: branch targets / fall-throughs of function code that Ghidra had left undecoded are
   disassembled (67), clearing misaligned instructions from bogus flows that are not in a catalogue
   function (191) where they block the decode.
6. Bodies recomputed with `CreateFunctionCmd.getFunctionBody` (flow from the entry, stops at other
   entries), two passes; the flow-derived body is dumped even when `setBody` refuses it because it
   overlaps another body (39 functions, 3 live).

`callgraph.py build` then: a stub's extent = stub (5 bytes) + its `.HOODLUM` body; a capstone
recursive-descent pass completes bodies whose direct branches / fall-throughs still leave the Ghidra
body (17 functions, 7,881 bytes, marked `ghidra+completed`). Result: 9,888 `ghidra`, 2,040
`ghidra-created`, 17 `+completed`, 0 fallback spans. Range-end audit: every body range ends in
ret/jmp/int3, except 6 that end on a call to a genuinely non-returning function (padding follows) and 6
that fall straight into the next catalogue entry (shared tails).

### 2. Call graph (capstone over the body ranges)
Edge kinds:

| kind | rows | sites | meaning |
|---|---:|---:|---|
| `call` | 31,275 | | direct `call rel32`; `.HOODLUM` targets mapped back to their game stub |
| `tailcall` | 811 | | `jmp`/`jcc rel32` to another function's entry outside the body |
| `import` | 208 | | `call/jmp [IAT]` (106 distinct imports incl. delay-load), callee = `DLL!name` |
| `virtual` | 223 | 305 | `call [vt+off]` where vt = `*this` and `this` = ecx at entry of a member of a class with a gta-reversed vtable (`RH_ScopedVirtualClass`): the slot's implementation in that class's vtable |
| `virtual-override` | 363 | 786 | the same slot in every gta-reversed vtable of a class derived from it (primary-base chain from the headers) |
| `indirect-ghidra` | 48 | 52 | indirect call Ghidra resolved by constant propagation |
| `eh-unwind` | 1,874 | | host pushes an MSVC `__ehhandler` stub: direct callees of its FuncInfo unwind/catch funclets (destructors run on unwind) |
| `fnref` | 475 | | a function address used as an immediate (callbacks, `atexit` registrations); not a call |
| `indirect-unresolved` | 1,613 | 4,715 | one row per function, `sites` = number of unresolved indirect calls; per-site detail in `indirect-calls.csv` |

`this` is tracked by a forward must-dataflow over the body's CFG (Ghidra switch targets included); any
unmodelled write kills the token. Unresolved indirect calls are never given a target. Of the 4,715:
2,791 carry "virtual call pattern, slot N, object type not known statically" (`mov r,[obj]; call
[r+off]`), 39 are `this`-vtable calls in a class without a gta-reversed vtable, 11 name the global
function pointer they call through (e.g. `0xc9e1f3` in `_TEXT_HA`), 1,874 have no pattern (`call reg`,
loaded pointers).

Calls out of game code, by callee class (direct call/tailcall sites): `excluded:crt` 4,913,
`excluded:thirdparty:quicktime-qtml` 36, `…libpng+zlib` 33, `…d3dx9` 17, `excluded:linker-thunk` 16,
`excluded:mis-split` 1, `noncatalogue` 28, `noncatalogue:hoodlum` 47, `noncatalogue:protection-text` 4.

Cross-check against Ghidra's own CALL references from the same bodies: 2 not in our edges, both
`.HOODLUM` bodies jumping into SecuROM code at 0xcb73e0 (recorded as `jump-outside-body`).

### 3. Global read/write sets
Every memory operand whose displacement lies in `.rdata`, `.data` (incl. bss), `_TEXT_HA`, `_rwdseg`,
`.rsrc` or the protection `.data2`. `mode`: `direct` (`[abs]`), `indexed` (`[abs + idx*s]`, address =
array base), `based` (`[reg + abs]`, abs ≥ 0x858000, address = array base). `access` from capstone
operand access: `R`, `W`, `RW`, `size` = operand bytes; `lea` and immediates that fall in a data
section are `A` (address taken, size 0). Totals: 42,677 rows, 13,282 distinct addresses; R 25,578,
W 7,490, RW 231, A 9,378.

Names: 2,439 data addresses named from gta-reversed (`StaticRef<…>(0x…)`, `*(T*)0x…`,
`reinterpret_cast`, class-qualified via the enclosing class) and plugin-sdk (`T& C::x = *(T*)0x…`,
`GLOBAL_ADDRESS_BY_VERSION`); gta-reversed wins. 14,600 rows carry an exact name. `near` gives
`name+off` for the closest named address ≤ 0x400 below. It is only a navigation hint, not a claim that
the access is a member of that object.

`writes_through_pointer` (extents.csv) counts memory writes with a base/index register, excluding
`esp`-based ones and `ebp`-based ones in functions with a `push ebp; mov ebp, esp` frame; 6,294
functions have at least one.

### 4. Port order
Graph over the 11,945 live functions with edges `call, tailcall, virtual, virtual-override,
indirect-ghidra, eh-unwind` (not `fnref`, not unresolved). Tarjan SCCs, level = 0 for SCCs with no
outgoing edge, else 1 + max(successor level). `scc_id` is assigned in (level, lowest address) order.
Result: 44 levels, 3,926 functions at level 0; 15 non-trivial SCCs holding 64 functions. The largest
two (12 each) are the explosion cycle (`CExplosion::AddExplosion` → `CWorld::TriggerExplosion` →
`CObject::ObjectDamage`/`CVehicle::InflictDamage` → `*::BlowUpCar` → `AddExplosion`) and the frontend
init cycle (`Rs/Ps` init, `CMenuManager`, `CText::Load`).

## Verification: spot check against gta-reversed

`spotcheck 10 SEED` takes 10 random reversed hooks with a findable source body. Every class-qualified
call (`C::f(`, or an own-class method) and every named global mentioned in the source must appear in
`callgraph.csv` / `rwsets.csv`. A global counts if accessed exactly or inside its object (≤ 0x400).
Members of other objects (`x.f`, `p->f`) are not checked.

Seed 7: calls 4/6, globals 21/22. Seed 2026: calls 7/9, globals 14/14. Every miss was examined:

| function | miss | explanation |
|---|---|---|
| 0x531bc0 `CControllerConfigManager::DeleteMatchingVehicle_3rdPersonControls` | `GetIsKeyBlank` 0x52f2a0 | inlined in the original: the body has its `cmp eax,3` / `cmp edx,0x420` switch inline |
| 0x43c710 `CCurves::CalcSpeedScaleFactor` | `DistForLineToCrossOtherLine` 0x43c610 | inlined (x87 code inline, reads the same constant 0x858b50) |
| 0x45dde0 `CReplay::IsThisPedUsedInRecording` | global `buffer` 0xbc40d8 | checker false positive: the source's `buffer` is a loop variable; 0xbc40d8 is a function-local `StaticRef` named `buffer` in FileLoader.cpp |
| 0x73db40 `CWeapon::Update` | `StopWeaponEffect` 0x73b360 | inlined: Update calls `FxSystem_c::Kill` (0x4aa3f0) directly, twice |
| 0x705d20 `CShadowCamera::MakeGradientRaster` | `GetRwRenderRaster` 0x705770 | 3-instruction accessor, inlined |

No miss is a tool error. One earlier miss, `CEventStuckInAir::TakesPriorityOver` →
`GetEventPriority`, came from a linear `this` tracker that lost `this` at a jump target. It led to the
CFG dataflow, and the call now resolves to slot 2 of vtable 0x85b508 → 0x4b1600.
`CTimer::Update` was also checked by hand: 29 accesses to 20 `CTimer::*` statics, all named.

## Blind spots

- **Indirect calls**: 4,715 of 5,062 indirect call sites stay unresolved (1,613 functions). Most are
  virtual calls on objects other than `this`, or on `this` in classes without a gta-reversed
  vtable. The port order therefore does not see most virtual dispatch, so a level-0 function can still
  reach code through a vtable. Resolving these needs object types (decompiler + type propagation)
  or runtime tracing (INF-10).
- **`virtual-override`** lists only classes with a gta-reversed `RH_ScopedVirtualClass` vtable, through
  primary-base chains parsed from headers.
- **Computed jumps**: 93 jumps stay unresolved (Ghidra found no switch table), so their targets may be
  missing from bodies. They are listed in `indirect-calls.csv` as `unresolved-computed-jump` and
  counted per function in extents.csv.
- **SecuROM**: displaced fragments are now part of host bodies, so the obfuscation's key reads show up
  as `.data2` / `_TEXT_HA` accesses in host rwsets (section column). Two `.HOODLUM` bodies jump into
  the protection `.text` (0xcb73e0) and are not followed. 47 calls from `.HOODLUM` bodies go to
  `.HOODLUM` code that is not a stub target (`noncatalogue:hoodlum`).
- **Catalogue gaps**: 153 game-code addresses are called (20), tail-called (1) or are vtable slot
  implementations (132) but are not procedures in `procedures.csv`. Examples: 0x41c050, 0x411330, and
  many CEvent*/CTask* slots in 0x4ac6b0–0x4b8330. They have no extents or port-order rows. List:
  `catalog/raw/cat7-noncatalogue-targets.csv`. One is CRT (0x82263a, `_purecall`: `push 0x19; call
  _amsg_exit`). **Closed by CAT-12** (see `cat9-12-pipeline.md`): all of them, plus 416 callees, 351
  vtable slots and 46 further call targets, are now catalogue rows; `noncatalogue_targets` = 0, and the
  `.HOODLUM`/protection call targets are classified `excluded:protection-thunk` (SecuROM).
- **Immediates**: the exe has no relocations, so an immediate inside a data section counts as an
  address (`A`, mode `imm`). A rare constant in 0x858000–0xCB0000 could be counted wrongly.
- **Bodies** are flow-derived: data reached only through pointers is not code, and code reached only
  through unresolved computed jumps is not in the body. Overlapping bodies (shared tails) are counted
  in each function.
- Stack/argument memory and pointer-based globals (`[reg+off]` with a small offset) are outside the
  rwsets apart from the writes-through-pointer count. L2 snapshots (INF-8) need runtime sets for those.
