# PORT-AI-1: AI subsystem, first pass (crate `sa-ai`)

First pass over the executed AI functions (RE-SPEC-AI pass 1: 564 spec'd functions in `docs/re/specs/AI/*.md`,
prioritised by `catalog/samp-priority.csv` and the corpus), leaves and small virtuals first, then sub-task
creation/control of executed tasks. Follows ADR-001 and the PORT-POP / PORT-WEAPON-PED pattern; ports follow the
1.0 US bytes (objdump/capstone of the exe incl. `.HOODLUM` and the protection islands), gta-reversed and the specs
only as reading aids. The main session sets `catalog/state.csv`; per-function verdicts are in
`docs/arch/ai-port-verdicts.tsv` and the table at the end.

## Crate

`crates/sa-ai` (PLAN §2 name). `#![no_std]`, `#![deny(unsafe_code)]`, host + i686 (`in-process`) + wasm32. Depends on
sa-core, sa-math, sa-macros and sa-world (byte-offset accessors). Every call into another catalogued function goes
through `orig!` at the original address (including functions this crate ports), virtual calls through
`orig!` `vslot`. Task and event objects keep the original vtables and come from the original pools
(`CTask::operator new` 0x61A5A0 / `CEvent::operator new` 0x4B5620 or the inlined `CEventPool::New` where the bytes
inline it). sa-hook appends `sa_ai::hooks::ALL` after sa-anim's (`table.rs` `build`, `callers.rs`), sa-oracle's
`hook_preserve` chains it. **Merge note:** master registers sa-veh after sa-anim; sa-ai must go after sa-veh there.

The generator for `trivial.rs`/`dtors.rs` matches every body instruction by instruction (patterns: `mov eax, imm;
ret`, `mov al, 0/1; ret N`, `xor al/eax; ret N`, `mov/movzx eax, [ecx+X]; ret N`, `fld [ecx+X]; ret`, `mov [ecx],
vtbl; jmp base`, the 11-instruction task and 30-instruction event scalar deleting destructors, `mov eax,
[0x86F648]; mov [g], eax; ret`); anything else was ported by hand.

## Conventions and findings

- **RNG**: every `rand()` names its original return address (`orig::at_site`): `CTaskSimpleCarDrive::TriggerIK`
  0x63C5DC only for car missions 2..6 (missions 0xF/0x10 through `GetRandomNumberInRange` 0x407180, others none);
  `CTaskSimpleFacial::ProcessPed` 0x692EC3 and 0x692EEB (second only when the first roll < 40);
  `CTaskGangHasslePed::CreateNextSubTask` 0x6642E0 (on every call, also when it returns null);
  `CTaskComplexObserveTrafficLights::CreateNextSubTask` (`GetRandomNumberInRange(3000, 5000)` on the 0x190 path,
  before the allocation); `CPedGroupMembership::GetObjectForPedToHold` 0x5F6956; `CInformFriendsEventQueue::Add`
  0x4AC23A; `CEventScanner::CEventScanner` 0x6053A3 (time read before the draw); `CDecisionSimple::MakeDecision`
  0x6007F2. The all-ports runs (rand caller hash included in the 17 subsystem hashes) are identical.
- **Original behaviour kept**: `CTaskComplexGangFollower::Clone` (0x65ECB0) writes through a null result when the
  task pool is full; `CTaskComplexBeInCouple::MakeAbortable` (0x6847C0) never asks its sub-task and returns true;
  `CTaskCategories::ComputeTaskCategory` (0x698680) makes three `GetTaskType` calls without a null check;
  `CTask::IsGoToTask` calls `GetTaskType` twice; `CTaskManager::FindActiveTaskByType` walks only the first non-null
  primary chain then the 6 secondary chains and makes one extra `GetSubTask` call after a match;
  `FUN_005bd360` compares LH/LL/LG against a zero-extended byte (never matches, returns 7);
  `CEventHandler::ComputeSexyPedResponse` keeps `m_EventResponseTask` on a null source; `CDecisionSimple::MakeDecision`
  compares the event id against the leading dwords.
- **Protection islands**: entries that start with `nop; jmp island` / `push -1; jmp island` or continue through an
  island (0x6532D0, 0x6836F0, 0x66AF60, 0x61A360, 0x6822B0 via 0x40806B, 0x4ABAC0 via 0x403C75, 0x607050 via
  0x406A7C, 0x4684F0, 0x4AE070) were followed: every island is straight code (SEH handler push, a register load,
  a compare) that jumps back; none computes a target at run time.
- **Catalogue name**: 0x460D80 is catalogued as the `CTaskComplexWanderCop` constructor but its body is the
  complete destructor (spec NAME CORRECTION); ported as the destructor under the catalogue name.
- **Preserved registers** (sa-hook `callers` test): `preserve = "edx"` on 0x5F7200, 0x61B460 (caller compares EDX
  with -1), 0x668250; `preserve = "ecx"` on 0x5BD3B0 and on 0x5BD360 (`CTaskSimpleFight::LoadMeleeData` keeps a
  table index in ECX across both calls; the `callers` test missed it, the weapon-combat L3 run found it).
- **`CDecision::MakeDecision` family is void**: 0x6040D0 leaves EAX = the facial pointer or its callee's EAX,
  0x606060 / 0x606E70 pass it on; no caller reads it (0x4B5725 returns it from `ComputeResponseTaskType`, whose
  callers 0x4AB496 / 0x5FAAC0 overwrite EAX), so the ports return nothing. `FUN_00606060` is ported but not
  registered: its split pairs differ in the task out-parameter (grove 2/72, c-bug 146/146), unresolved.
- **Stack objects**: ports that build a temporary object on the original's stack use a Rust local buffer
  (0x63C670 `CTaskSimpleCarSetPedOut` 0x18 bytes, zeroed where the original's is uninitialised before its
  constructor; 0x647330 `CUpsideDownCarCheck`; 0x61BF20 bone vector; 0x650A80 `CMatrix` + vectors; 0x641FC0
  `CEventGroupEvent`; 0x606F80 passes locals where the original passes its own dead argument slots). 0x61B770
  `CTaskSimpleRunNamedAnim::Clone` passes a bool argument zero-extended where the original pushes leftover EDX in
  the upper bytes.
- **In-text `jmp rel32` entries**: sa-hook classes a bare `E9` entry as a `.HOODLUM` stub; 0x674920 / 0x6823B0 are
  hooked with the following `nop` in `expect` (inline kind); 0x4AFB40, 0x48DE60, 0x48EA90 were left unhooked.

## Unhookable (ported, not registered)

Entries whose code up to `ret` is shorter than the 5-byte patch (`ret 4`, `xor eax,eax; ret`, `mov eax,[ecx+X];
ret`, ...), protection reads of the patched bytes (INF-20: `CEventAcquaintancePedHate::GetEventType` 0x420F40,
`push 0x420F44` at 0x146747B; `CEventAcquaintancePedHate::CloneEditable` 0x420F50, `push 0x420F54` at 0x14674BE;
`CEventEditableResponse::~CEventEditableResponse` 0x4AC480, read at 0x407EA1, and its caller 0x4B5671 reads ECX),
and the three bare-`jmp` entries above. Each row says which.

## Harness notes (for the harness slot, not ledger)

- The first plain-`l2` run crashed: helper-classified "l2" functions that allocate or free pool slots (event
  `Clone`, scalar deleting destructors) or write through a non-`this` pointer argument
  (`CTaskSimpleEvasiveStep::FinishAnimEvasiveStepCB`, task pointer at `[esp+8]`) cannot run twice on the same
  state; the lists now put every function that writes or calls into split mode.
- Split-mode verdicts are PASS-FP wherever the OS-handle pages 0x8E4000/0xB60000 differ between the two
  processes (known since PORT-WEAPON-PED); those rows stay `implemented` with 0 mismatches.
- `sa-oracle l2 split-report` loads both spools: two 6 GiB spools exceeded an 8 GiB scope (killed, no report).
