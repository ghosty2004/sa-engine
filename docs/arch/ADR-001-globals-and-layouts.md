# ADR-001: game state, layouts, calls into the original, hook registration

Status: accepted for implementation (ARCH-1, 2026-11-05). Implemented in `crates/sa-core` (`mem`, `orig`,
`abi`, `layouts`, `hooks`), `crates/sa-macros` (`#[hook]`), `tools/gen/layouts_rs.py`, and the
`Group::Port` part of `crates/sa-hook/src/table.rs`.

## 1. Problem

Every engine crate (sa-core now, sa-world, sa-ped, … later) must be written once and run in three
settings:

- **Phase A** (in-process strangler, PLAN §2): Rust shares gta_sa.exe 1.0 US's address space. Game
  state is the original's memory: globals at fixed `.data`/`.bss` addresses, objects in the game's heap
  and pools, all in the original layout. A ported function is entered from original code with the
  original calling convention, and it calls functions that may still be original. Each function's
  hook switches between Rust and original at runtime (L2/L3 and the hook-off check need that).
- **Phase B** (standalone native) and **phase C** (wasm32): no original code, no fixed addresses,
  engine-owned memory.

Constraints: no per-function duplication between phases; FEASIBILITY §3.3's two-layer rule (layout- and
ABI-faithful while sharing the process); x87 results must be returned exactly; determinism mode
(docs/re/determinism.md) must keep working, including its rand caller hash and its virtual clock call
sites; `unsafe` as contained as possible.

## 2. Options considered

| | A. `Globals` struct of `&'static mut` resolved at startup | B. Explicit engine context `&mut Ctx` passed to every function | C. Per-global accessor (`Global<T>`) whose storage is chosen per phase (**chosen**) |
|---|---|---|---|
| Phase A | addresses from a table, references created once | the context must be fetched from a global in every hook shim anyway | `addr as *mut T` |
| Phase B/C | one allocation | natural | a Rust-owned static per global, declared by the same line |
| Port code | `g.timer.time_ms += …` | `ctx.timer.time_ms` | `TIME_MS.get()`, `TIME_MS.set(..)` |
| Soundness | **unsound in phase A**: a `&'static mut` to memory that original code writes between Rust accesses violates the aliasing rules the moment any original function runs | fine in B; same issue as A for the game-memory parts in phase A | no reference outlives one access (copy in/out), so original code running in between cannot invalidate anything Rust holds |
| Signature change vs. the original | none | every ported function gains a parameter; original callers cannot pass it | none |
| wasm | fine | fine | fine (static storage in linear memory) |

A was rejected for aliasing unsoundness (and because one big struct makes every crate depend on every
global). B was rejected because it changes every signature and phase A must still materialise the context
from a global in each shim, so it buys nothing until phase B; it remains possible later: phase B can turn
the per-global storage into fields of one context without touching port code (only `__global_store!`
changes, see §3).

For calls into possibly-original functions: (i) call the Rust implementation directly, (ii) call through
the original address, (iii) a typed declaration that is (ii) in phase A and (i) in phase B (**chosen**).
(i) breaks the hook-off check (a Rust caller would bypass the callee's toggle) and makes phase A call
unported functions that do not exist. (ii) alone does not build for phase B/C.

For hook registration: (a) one central hand-written table (today's `sa-hook` style; duplicated
signatures, error-prone), (b) linker-section collection (`inventory`/`linkme`; life-before-main in a DLL,
order not fixed), (c) an attribute next to the function plus an explicit list per crate checked by a test
(**chosen**: deterministic order, no runtime registration, one place per function carries address, name,
convention and entry bytes).

## 3. Decision: game state

- **`mem::Global<T>`**, declared with `sa_core::globals!`:
  ```rust
  globals! {
      list TIMER_GLOBALS;
      /// `CTimer::m_snTimeInMilliseconds`
      pub static TIME_MS @ 0xB7CB84: u32 = 0;
  }
  ```
  One line gives the 1.0 US address, the type, and the initial value of the original image (`.data`
  contents, 0 for `.bss`). Phase A: `ptr()` is the address. Phases B/C: a hidden `static mut` initialised
  with that value (generated by `__global_store!`, the single place to change if phase B moves globals
  into a context). `list` emits a `&[GlobalDesc]` (name, address, size, initial bytes) so a test can
  compare initial values with the exe image.
- **`mem::GPtr<T>`**: a C++ `T*` (field or argument). `#[repr(transparent)]` over `*mut T`: 4 bytes on
  i686 and wasm32, passed in registers like `T*`. Pointer math follows the original's 32-bit wrapping
  (`wrapping_index`, `index_from` = signed 32-bit difference / `sizeof(T)`, as MSVC's magic-number
  division computes it — checked against the exe's multiply/shift sequences on 9M inputs).
- **`mem::GameData`** (unsafe marker trait): types where every bit pattern is valid (integers, floats,
  `GBool` = a C++ `bool` byte, raw/game pointers, `Option<fn>`, arrays and `#[repr(C)]` structs of these).
  Reads of original memory can therefore never produce an invalid Rust value (a C++ `bool` holding 2 is
  fine as `GBool`, UB as `bool`).
- **Layouts**: every type shared with original code is `#[repr(C)]` in the original layout until its
  subsystem is fully owned (two-layer rule). `tools/gen/layouts_rs.py` turns `catalog/layouts.csv` into
  `sa_core::layouts::{size, offset}` constants (781 sizes, 39 offsets at the time of writing) and emits compile-time assertions
  for the Rust mirrors listed in its `ASSERTS` table; structs holding pointers are asserted on 32-bit
  targets only (a 64-bit phase B build may lay them out natively). Field offsets read from the
  disassembly are asserted next to the type (e.g. `CPool`).

**Trust model (the safety story).** Phase A cannot be proven sound by Rust: a game pointer is valid
because the original program's invariants say so, exactly as in the C++ being replaced. sa-core makes
that explicit instead of scattering `unsafe`:

1. `#![deny(unsafe_code)]` crate-wide; `unsafe` is allowed only in `mem` (memory), `orig` (calls into
   original code), `abi` (MXCSR guard) and in the expansions of their macros. Port modules (`pool`,
   `timer`, `general`) contain no `unsafe` except one `unsafe impl GameData` for a POD struct and the
   call through the stored timer function pointer.
2. All game-memory access goes through `Global::{get,set}` and `GPtr::{read,write}` — one audited place,
   also the natural instrumentation point for L2 read/write-set recording (INF-8).
3. Single game thread: the original game loop is single-threaded; sa-hook runs a port on the thread
   that called the original. Accessors must not be used from other threads (sa-hook's control thread
   uses its own `peek`, never `Global`).
4. No Rust reference into game memory outlives one access. `&mut` to game memory is not handed out;
   ports copy a header in (`pool.read()`), compute, and write fields back.

## 4. Decision: calls into possibly-original code (`orig!`) and hook registration (`#[hook]`)

```rust
orig! {
    /// CRT rand()
    pub fn rand() -> i32 = cdecl 0x821B1E => rand_owned;
    /// QueryPerformanceCounter as CTimer::GetCurrentTimeInCycles calls it
    pub fn query_performance_counter_cycles(out: GPtr<u64>) -> i32 = stdcall site 0x561A88 => unported;
}
```

- Phase A: a typed call to the original address with the declared convention (`cdecl`, `stdcall`,
  `thiscall`, `fastcall` → `extern "C"/"stdcall"/"thiscall"/"fastcall"`, x86 only). If the target is
  hooked, **its** toggle decides Rust vs. original, so one switch per function also governs calls made
  from Rust, and the hook-off check stays meaningful.
- `site ADDR`: the target is read at call time from an original `call dword ptr [cell]` instruction.
  sa-hook's determinism mode redirects such call sites (virtual clock), so a port that calls an import
  "as the original call site does" gets exactly the same redirection.
- Phases B/C: the call goes to the Rust path after `=>`; `unported` is a panic naming the function
  (phase B only starts once F2 holds).
- **Caller attribution** (`orig::at_site(ret_addr, || …)`): determinism mode hashes `(caller, value)`
  of every `rand()`. A port names the original return address of the call it replaces (e.g. 0x407187
  in `GetRandomNumberInRange<int>`); sa-hook's rand/srand hooks use it when the real return address is
  not game code. Original and Rust runs therefore hash identically.

```rust
#[hook(addr = 0x404910, conv = thiscall, name = "CPedPool::GetAtRef", expect = "8B 54 24 04 53")]
pub fn ped_pool_at_ref(pool: GPtr<CPool<PedSlot>>, handle: i32) -> GPtr<PedSlot> { … }
```

`#[hook]` (proc macro in `sa-macros`) leaves the function as plain Rust (testable on every target) and
emits:

- on `target_arch = "x86"` only, a shim `extern "<conv>" fn` with the original convention (`this` is
  the first argument for thiscall). It counts the call, enters `abi::FpuGuard`, calls the function and
  converts the result with `abi::IntoAbi` (`X87` → `f64`, which the i686 C ABI returns in ST0 through
  `fld qword`, exact for every value of the 24-bit/extended-exponent model). Off x86 nothing is emitted,
  so the x86-only ABIs never reach wasm or x86_64.
- with `preserve = "edx"` (or `"ecx"`, `"ecx,edx"`), the registered entry is a naked wrapper around the
  shim that returns those registers unchanged, for original callers that keep a value in them across
  the call (VER-2; sa-hook's `callers` test finds such callers, see `docs/re/l1-harness.md`).
- `pub const HOOK_<NAME>: abi::HookReg` = address, catalogue name, convention, the entry bytes the
  installer must find, the shim address (0 off x86), the call counter, and the L2 signature data:
  stack argument words (from the argument types' sizes, after the register arguments), the return
  kind (`IntoAbi::RET`: Void/AL/EAX/EDX:EAX/ST0) and, with `this = "CPool<int32>"`, the `this` type
  and its size from `layouts::size`. sa-hook turns these into INF-8's `Sig`, so the `l2` hook mode
  works for engine-crate ports too (host replay of their L2 fixtures is not wired yet).

Each crate lists its registrations explicitly in `hooks::ALL` (a test counts `#[hook(` in the sources
against the list and checks unique addresses). sa-hook builds its table at compile time as
`LOCAL ++ sa_core::hooks::ALL` (const fn), derives `.HOODLUM` stubs from the entry bytes (`E9 rel32`),
and installs them as group `Port`:

- `SA_HOOK_PORTS` unset → ports not installed (the original runs exactly as before ARCH-1);
  `orig` → installed, original mode; `rust` → installed, Rust mode; `name,0xADDR,…` → those in Rust mode.
- Toggles: the existing control-channel `hook <name|addr> rust|orig`, applied at the frame boundary.
- Every registration is checked against the exe by sa-hook's tests: entry bytes, catalogue name and
  stub kind, the installer's relocation and inbound-branch checks, no overlapping patches.
- The trampoline keeps a stolen trailing `call` returning to the original address
  (`x86::relocate_keep_return`: `push ret; jmp target`), so `rand()` called from a hooked
  `GetRandomNumberInRange` in original mode still sees return address 0x407187.

### 4b. Register conventions (`conv = reg("...")`, HARNESS-5, 2026-11-11)

MSVC's whole-program optimisation gave many functions conventions no `extern` ABI describes: arguments
in EAX/EBX/ESI/EDI, a byte in AL or a word in DI, `this` in EAX or ESI, results in AL/AX whose upper
EAX bits are the caller's, an 80-bit ST0 result (FYL2X), callers keeping values in ECX/EDX/EAX across
the call. One spec string, parsed by `#[hook]` and by the const fn `sa_core::regconv::RegConv::parse`
(the expansion asserts both parses agree), describes such a function for both sides:

```text
args = ebx esi        one location per Rust argument, in order: eax ecx edx ebx esi edi ebp |
                      ax cx dx bx si di (2-byte type) | al cl dl bl (1-byte type) | stack
                      (omitted: every argument on the stack)
ret = al:entry        auto (default: from the Rust type) | al | ax (only the low part is defined) |
                      al:entry | ax:entry (EAX's upper bits = the caller's EAX at entry)
keep = ecx edx        caller-saved registers returned unchanged (eax only for a void result)
pop                   the callee pops its stack arguments (ret 4n); default: the caller pops
```

```rust
#[hook(addr = 0x5DBE40, conv = reg("args = ebx esi"), name = "CPlantMgr::_CalcDistanceSqrToEntity", ...)]
pub fn calc_distance_sqr_to_entity(entity: GPtr<u8>, posn: GPtr<u8>) -> X87 { ... }   // ST0, 80 bits
#[hook(addr = 0x70FA70, conv = reg("args = ecx edx di stack; keep = ecx edx"), ...)]
pub fn toggle_edge(edges: GPtr<u8>, count: GPtr<u16>, a: u16, b: u16) { ... }
#[hook(addr = 0x4D9E50, conv = reg("args = stack"), ...)]                    // cdecl + 80-bit ST0
pub fn audio_log10(v: f32) -> X87 { ... }
orig! {
    fn char_position(c: u8, col: GPtr<u32>, row: GPtr<u32>) = reg("args = al stack stack") 0x6FD7C0 => get_character_position_in_char_set;
}
```

- **Results**: integers and pointers in EAX, u64 in EDX:EAX, `bool`/u8 in AL, f32/f64 in ST0 (exact),
  `sa_math::x87::X87` in ST0 **with all 80 bits** (`fld tbyte`, so a 64-bit FYL2X/FPTAN value survives;
  the standard conventions still return it as an f64 through `IntoAbi`). EAX/EDX not carrying the
  result come back as the caller passed them; EBX/ESI/EDI/EBP always do.
- **Phase A hook entry** (i686, generated by `sa-macros`): a naked function that sets up EBP, pushes the
  `keep` registers and ESI/EDI, reserves a 16-byte aligned `regconv::RegOut` slot initialised with the
  caller's EAX/EDX, stores the register arguments as words and `rep movsd`-copies the stack arguments
  into an `extern "C"` shim's frame (`shim(out, register words..., stack arguments...)`), calls it, loads
  EAX/EDX (and ST0 when the shim set it) from the slot, restores and returns with `ret` / `ret 4n`. The
  shim narrows each register word to its type (`FromRegWord`), runs the port under `FpuGuard` and writes
  the result (`RegReturn`; the `:entry` modes overwrite only AL/AX).
- **Phase A `orig!`**: `regconv::call_regs` loads EAX..EDI and the stack words from a `RegFrame`, calls
  through `[ebp-8]` (EBP is its frame pointer, so an `orig!` spec cannot pass an argument in EBP),
  captures EAX..EDI, the ESP delta and (for a float/X87 result type) ST0 as 80 bits, popped. Runs under
  `call_original` like every `orig!` call. `#[hook(fallback)]` works with `reg` too.
- **Phases B/C, host tests**: no wrapper, no thunk; the registers are the Rust arguments.
- **Registration**: `HookReg::regs = Some(RegConv)`; `conv` is `Cdecl` (caller pops) or `Stdcall`
  (`pop`), `stack_words`/`arg8`/`arg16` count the stack arguments only (i686 word counts on every
  target), `preserve` = the `keep` ECX/EDX bits (so the callers scan and the L1 preserve rule apply),
  `ret` = the mode's `AbiRet` (`al:entry`/`ax:entry` compare a whole EAX, `ax` the low word). L2's
  `Sig::this_reg` names the register of argument 0 for the `this` snapshot; split-run matches every
  input register (over the bytes its location covers).
- **Checks**: `sa-core` unit tests call every variant's naked entry through `call_regs` on
  `i686-unknown-linux-gnu`; sa-hook's `regconv_check` compares each spec with the exe (declared
  registers read before written, no undeclared register input, `ret n` = the declared cleanup, and no
  caller reads EAX bytes the hook leaves undefined; its walker follows switch tables and steps over
  indirect calls, treats `mov edi, edi` as a no-op and, for `al:entry` / `ax:entry`, does not count
  reads of the EAX bytes kept from the entry as inputs (WRITER-REGCONV)); L1 specs set entry registers with
  `Call::regconv` (Unicorn and native backends: context block bytes 128..152).
- Not expressible (open): results in registers other than EAX/EDX/ST0, callee-saved registers the
  original changes on purpose (an output in ESI), more than one x87 result, `footprint`/`peek`/
  `preserve`/`entry_eax` together with `reg` (use `keep`/`:entry` instead).

## 5. FPU environment of ports (phase A)

The game runs with x87 CW 0x007F (PC = 24) and MXCSR 0x9FA0 (FTZ on). Original code is x87, which MXCSR
does not affect; Rust compiles f32/f64 arithmetic, including the `sa_math::x87::X87` model, to SSE,
where FTZ would flush subnormal results (e.g. `X87::to_f32` of an f32-subnormal value). The hook shim's
`FpuGuard` clears FTZ/DAZ on entry and restores the caller's exact MXCSR (sticky flags included) on exit,
so a port leaves MXCSR as the x87 original would. Hooks written before ARCH-1 (`sa-hook/src/game.rs`) do
not use the guard; sa-math functions called from them run under FTZ.

### 5b. Stack residue read by original code (`footprint`, 2026-11-11)

Original code sometimes reads uninitialised stack slots, so its behaviour depends on what an earlier
callee left below its entry ESP (e.g. `CWeapon::FireInstantHit` 0x73FB10 passes a never-written shot
direction local to `AddGunshell`; on c-bug frame 2494 that slot holds `RwV3dNormalize`'s residue, and a
Rust shim leaves a frame-layout-dependent one: changing `X87` from 8 to 16 bytes moved the divergence).
Rule: when such a reader is found, the port of the callee whose residue it reads is registered with
`#[hook(..., footprint = W)]` and calls `sa_core::abi::stack_footprint(&[(offset, value), ...])`,
1:1 from the disassembly: every slot the original writes, relative to the entry ESP (negative = below
the return address, positive = argument slots), in the original's order, with `Fp::Esi`/`Edi`/`Ebx`/
`Ebp` for pushed callee-saved registers and `Fp::Addr(o)` for pushed addresses of its own locals. The
naked wrapper snapshots the `W` bytes below the entry ESP (`W` covers the whole depth the Rust shim and
its callees use, e.g. 0x800, so no Rust frame survives), calls the shim, puts the snapshot back (slots
the original never writes keep their earlier residue), applies the recorded writes, and returns with the
shim's EAX/EDX/ECX/ST0. Limits: residue the original's callees leave deeper than the window, or that
depends on their internal paths, is documented per port; footprint hooks run on the main thread, may
nest (each hook has its own state; `FOOTPRINT_CUR` names the innermost, PORT-CAM-3: `CCam::Process` calls
original code that calls `RwV3dNormalize`) but must not recurse into themselves, and cannot be combined with
`preserve`/`entry_eax`. Phases B/C: no wrapper, the call records
nothing. Diagnose readers with `SA_COV_PEEK` (docs/re/l2-oracle.md).

## 6. Phase B/C path (what changes later, and what does not)

Unchanged: every port's source, every `globals!`/`orig!`/`#[hook]` line. Changes: `__global_store!`
(context instead of statics if wanted), the `=> path` targets of `orig!` (platform functions instead of
`unported`), the 64-bit layout of pointer-holding structs (allowed: the asserts are 32-bit only),
`#[hook]` shims disappear (no x86). wasm32 builds today (`cargo build -p sa-core --target
wasm32-unknown-unknown`).

## 7. Consequences and open points

- New engine crates depend on sa-core and use `#[hook]` with `sa_core` in scope; sa-hook appends their
  `hooks::ALL` the same way (one line in `table.rs`'s `build`).
- `GPtr::read/write` are safe functions under the trust model; a wrong pointer in a port is as fatal as
  in the C++. L2 (INF-8) is the check.
- `Global` has no runtime thread check (no_std, cost); a debug-build check of the game thread id in
  phase A is possible later.
- `orig::import_at_call_site` asserts the `FF 15` opcode at runtime on every call; a site table checked
  once at attach would be cheaper.
- Partial ports (2026-11-11): `#[hook(..., fallback)]` gives a port a callable original body for the
  paths it has not ported (the original-mode trampoline). See `ADR-002-partial-ports.md`.
