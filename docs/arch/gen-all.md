# Generated ports for every subsystem but AI (`tools/gen/patterns.py`)

AI-GEN (`docs/arch/ai-gen.md`) generated sa-ai hooks from the exe bytes with an exact symbolic x86
interpreter. `tools/gen/patterns.py` holds that interpreter and its Rust emitter as a shared module plus a
driver for WORLD, COLL, PHYS, VEH, PED, POP, RENDER, HUD, CAM, AUDIO, STREAM, CORE, ANIM, INPUT, WEAPON,
SCRIPT and RW, and the UNK-game rows by their proposed subsystem (`catalog/unk-classification-proposal.csv`).
The generated Rust holds only semantics (offsets, constants, vtable addresses, callee addresses); the exe
is read at generation and test time and never copied. A first run (GEN-ALL, 1,607 functions) was never
merged; the driver was brought to master and re-run against it as GEN2 (counts below).

Every generated hook is **unverified** (docs/PLAN.md §5.1, docs/verify/HOWTO.md): it carries
`unverified = "gen2-<subsystem>-<n>"`, `route`, `hazards` and, where INF-10 coverage shows a call, `recs`.
Phase A installs none of them unless a run selects them (`SA_UNVERIFIED`); verifiers promote them batch by
batch from `docs/verify/QUEUE.md`.

## Generator

- `.venv/bin/python -I tools/gen/patterns.py [--check]`. The output goes through the repository's
  `rustfmt` (edition 2024, `rustfmt.toml`), so `--check` compares exactly what is on disk; two runs are
  byte-identical (address order, no unsorted set reaches the output). It never overwrites a file that does
  not carry its mark (`Generated by \`tools/gen/patterns.py\``) and removes its own stale files.
- `tools/gen/ai_patterns.py` and `tools/gen/audio_patterns.py` are unchanged (they keep their own copy of
  the interpreter; `ai_patterns.py` counts every file but `gen_*.rs` as ported, so it never duplicates a
  hook generated here).
- Crate mapping (`SUBSYS_CRATE`): CORE sa-core, STREAM sa-stream, WORLD/COLL/PHYS sa-world, POP sa-pop,
  SCRIPT sa-script, WEAPON sa-weapon, PED sa-ped, INPUT sa-input, ANIM sa-anim, VEH sa-veh, HUD sa-hud,
  CAM sa-cam, AUDIO sa-audio, RW sa-rwcore, RENDER sa-render. MATH and SAVE rows are not generated.
- Skipped candidates:
  - the AI class families (`AI_NAMES`: they stay with sa-ai);
  - every address registered (`#[hook(addr` or `#[native(addr`, also over several lines) anywhere in
    `crates/` outside this generator's files;
  - every address in `tools/gen/exclude_inflight.txt`: `python3 -I tools/gen/inflight.py` reads `master`,
    every `worktree-agent-*` branch (blobs through `git cat-file`) and the uncommitted `crates/` of every
    agent worktree, and lists what they register and this checkout does not (files of this generator do
    not count, so an older generator branch cannot hide its own candidates). Regenerate it, then
    `patterns.py`, right before merging;
  - every `catalog/state.csv` row at implemented/L1/L2/L3/excluded not set by this generator;
  - AUDIO-GEN's scope (`audio_patterns.py`: the sound output/decoding classes, its excluded,
    ported-unhooked and skipped addresses, read from its source).
- Output per crate: `src/generated.rs` (the hub: `#[path]` modules, the helpers `p`/`rd`/`wr`/`g`/`x` on
  `sa_core::mem::GPtr`, `HOOKS`, `BODIES` and the `bodies_match_the_exe` test) plus one file per content
  class with at least 3 generated functions in the crate (`<class>_generated.rs`: the C++ class, or the
  RenderWare object of an `Rw*`/`Rp*`/`Rt*`/`Rx*` function, e.g. `rp_world_generated.rs`) and one file per
  pattern family for the rest (`generated_leaves`, `generated_setters`, `generated_leaf_logic`,
  `generated_ctors`, `generated_dtors`, `generated_inits`, `generated_thunks`, `generated_small`).
  Registration: `pub mod generated;` in the crate's `lib.rs` and `crate::generated::HOOKS` as the last
  `MODULES` entry of its `hooks.rs`.
- `crates/sa-oracle/src/specs_generated.rs`: one L1 spec per `L1-pure` hook (random argument words; EAX
  or AL and the declared preserved registers compared), chained into `specs::all()`.
- Reports: `target/gen-patterns/report.tsv` (every generated function: address, name, ident, family,
  hook or unhookable reason, subsystem, crate, file, stub/inline, convention, stack arguments, return
  kind, calls, stores, batch, route, hazards), `rest.tsv` (every candidate not generated, with the reason)
  and `counts.txt` (per subsystem and family, and the rejection reasons).

### Verifier hints

| attribute | rule |
|---|---|
| `unverified` | `gen2-<subsystem>-<n>`: per subsystem, hooks in file then address order, split evenly into batches of at most 60 |
| `route` | `L1-pure`: the body reads, writes and calls nothing (arguments and constants only) and uses no x87; `split`: static initialisers and `atexit` destructors of globals (one-time code); `L2`: everything else |
| `hazards` | `preserved-regs` (`preserve` declared), `ax-al-return` (AL result, the caller's upper EAX), `heap-writes` (a store through a pointer rather than to a fixed global), else `none` |
| `recs` | the recordings whose INF-10 coverage (`catalog/raw/coverage-*.csv` of the data checkout) shows a call; omitted when none does (queue.py then starts with grove-walk) |

### Families (one per function, by name first, then by shape)

| family | rule |
|---|---|
| `dtor` | `~X`, `Destructor`, `__dtor_*` (atexit destructors of globals), scalar deleting destructors; or a vtable store to `[this]` followed by a call |
| `pool` | `operator new` / `operator delete` |
| `ctor` | `Constructor*` or `C::C`; or a vtable store to `[this]` and every path returns `this` |
| `static-init` | `__init_*` (CRT initialisers of globals) |
| `const` / `const-bool` / `empty` / `getter` / `getter-f32` | no call, no store, no branch: constant EAX / constant AL / nothing / a loaded value / ST0 |
| `setter` | stores only (no call, no branch) |
| `leaf` | no call (branches, switch tables and stores allowed) |
| `thunk` | exactly one call whose result is returned, nothing else but loads |
| `small` | at most 4 calls and 40 statements in the subset |

### Extensions over AI-GEN

- **x87 subset** (`X87_EXT`): `fld`/`fild` dword from memory, `fld1`, `fldz`, `fld st(i)`, `fchs`,
  `fadd`/`fsub`/`fsubr`/`fmul`/`fdiv`/`fdivr` with a dword memory operand (the `sa_math::x87::X87` `_m`
  forms), the commutative register forms `fadd`/`fmul`/`faddp`/`fmulp` with ST0, `fxch`, `fst`/`fstp`
  dword to memory, `fstp st(0)`. The register stack must be empty at every call and tail call and hold at
  most the ST0 result at `ret`. The values are modelled as the game runs them (PC=24). Static
  initialisers run at CRT start-up (PC=53): a static initialiser with more than one x87 op on a stored
  value is rejected. Callees are declared `-> u32` only (no ST0 results are consumed).
- **Large constants** (`BIG_SUFFIX`): literals >= 0x8000_0000 get a `_u32` suffix.
- **ECX/EDX for callers** (`ghookable`): the interpreter records whether every path returns ECX and EDX
  unchanged. `tools/gen/patterns_callers.txt` lists the generated hooks whose original callers read
  ECX/EDX after the call (the UNDECLARED rows of sa-hook's `callers` test, merged by
  `tools/gen/patterns_callers.py`); such a hook gets `preserve = "..."` when the original keeps the
  registers and the body is L1-pure (its generated spec compares them), and is left unhooked otherwise.
- **Forwarders into void ports** (VERIFIER-7): a function whose every return passes on the EAX of a
  tail call into a hand port registered without a result (`fn f(..)` with no `->`, `void_ports`) is
  generated void: the original returns whatever that callee leaves in EAX, the port leaves it undefined
  (split FAIL `eax: orig 0x1 rust 0x5db0c0` for `CGrassRenderer::FlushTriPlantBuffer` -> `CPPTriPlantBuffer::Flush`).
  Such a forwarder that takes nothing and does not read ECX (it sets ECX for its callee) is `cdecl`, as
  are free functions: ECX is not an input. 16 forwarders; no direct caller reads EAX after them (checked
  on the exe at generation time by hand; vtable slots: the base class's port is void as well).
  VERIFIER-10 extended the rule from tail calls to every return of a call result into a void port
  (`call; pop ecx; ret 4`: split FAIL `eax: orig 0x1 rust 0x4e6dc0` for `CAudioEngine::StopPoliceScanner`
  -> `CAEPoliceScannerAudioEntity::StopScanner`): 6 more functions are generated void.
- **Promotion** `tools/gen/patterns_verified.txt`: generated hooks a verifier promoted (address per line,
  evidence in `docs/verify/verdicts-gen2.tsv`), and own hooks whose `catalog/state.csv` row is L1/L2/L3, are
  generated without `unverified` (route and hazards stay; batch numbering is unchanged). VERIFIER-7 promoted
  539 of the 852 (25 L1, 514 split); the other 313 had no split case on grove-walk, pause-restart or
  save-load (27 of them `atexit` destructors, never called before ExitProcess) and stay `L3-batch`.
  VERIFIER-10 split the 282 non-atexit ones on the other 10 corpus recordings and promoted the 12 with
  cases (docs/verify/verdicts-gen2b.tsv); the rest are never called on any recording.
- **Own catalogue rows**: a `catalog/state.csv` row of an address this generator's own files register
  (the integration's `implemented` rows, L1/L2/L3 after promotion) does not hide it as a candidate.
- **Unhook list** `tools/gen/patterns_unhook.txt`: `0x41BF70` (`CCarAI::FindSwitchDistanceFar`: a call at
  0x40248E targets 0x41BF79, inside the patched entry bytes) and `0x748F50`
  (`RpAnisotTextureGetMaxAnisotropy`, l2 FAIL on the GEN-ALL branch). Neither is a candidate on master
  now (both are registered or catalogued elsewhere); the entries stay for a regeneration.

## Tests

- per crate `generated::tests::bodies_match_the_exe`: every generated function lists the spans it was
  matched on (stub, every executed instruction, switch tables) with a 64-bit FNV-1a hash; the test re-reads
  the exe and checks them all.
- per file `tests::pattern_{const,const_bool,empty}`: every such port is called and returns the constant
  the bytes load.
- sa-hook lib tests (install on the exe, catalogue match, `callers` ECX/EDX, keycells, INF-20
  `data_reads`, `patch_refs`, duplicate addresses across crates) with every generated hook registered;
  sa-oracle `--test l1` runs the generated L1 specs under Unicorn, the writer gate runs each `L1-pure` hook
  on the CPU (`--backend native`, 10^6 cases).
