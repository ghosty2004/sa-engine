## Crates (ADR-001 §7) and module layout

Two new crates, named as PLAN §2 fixes them: **`sa-input`** and **`sa-anim`** (both `no_std`, host / i686 /
wasm32, `#![deny(unsafe_code)]`). Why separate crates and not sa-world / sa-core: INPUT consumes CORE's input
glue (`sa_core::input` globals and `orig!` declarations) and is consumed by PED, VEH, CAM and HUD only through
`orig!`; ANIM is consumed by PED/VEH/CAM/SCRIPT and consumes CORE/STREAM/RW only through `orig!`. Neither needs
another engine crate at build time, so no engine crate depends on them, and the WORLD/PHYS worktrees' files
(`sa-world`) stay untouched (no merge conflicts). Each crate has the usual `hooks.rs` (`MODULES`, `GLOBALS`, the
"complete and unique", "declared once across crates" and "initial values = exe image" tests; dev-dependencies
on sa-stream / sa-world (/ sa-input) for the cross-crate checks).

## Conventions and findings

- **New hook option `entry_eax`** (sa-macros; `sa_core::abi::{ENTRY_EAX, entry_eax, set_entry_eax,
  with_entry_hi}`). Many `CPad` getters return a 16-bit value with `mov ax, ...` / `xor ax, ax` on a path where
  the upper half of EAX is still the caller's EAX (e.g. `GetSteeringLeftRight` with `DisablePlayerControls`
  set), and L2 compares the whole EAX. With `#[hook(entry_eax)]` the naked entry wrapper stores the caller's
  EAX (`mov [ENTRY_EAX], eax; jmp shim`; composable with `preserve`) and the port returns
  `(entry_eax & 0xFFFF0000) | ax` on those paths, so EAX is reproduced bit for bit. The L1 harness enters with
  EAX = the function address; the specs set the same value. Return-register rule used everywhere: whole-EAX
  results → `u32`, AL-only → `u8` (L2 compares AL), AX with the caller's upper half → `entry_eax`.
- **Entry bytes read as data by the protection** (scratch `dataref.py`: every disp32 / moffs operand in any
  section addressing a patched entry byte; plus `tools/e2e/cov-data-reads.py --hooks`): in this scope 0x4D3940
  `CAnimManager::GetAnimationBlock-` (`adc edi, [0x4D3940]` at 0x156F054) and 0x540120
  `CPad::ExitVehicleJustDown` (`xor ecx, [0x540123]` at 0x156640F): ported, not registered. Over all 1,276
  engine registrations the scan finds three more, in sa-stream: 0x410860 `CColStore::LoadCollision` (read at
  0x401E46), 0x407AD0 `CStreaming::AreAnimsUsedByRequestedModels` (0x401BCE, 0x40203A), 0x4C4570
  `CAtomicModelInfo::SetupVehicleUpgradeFlags` (0x1564881, 0x156B570) — the ones PORT-WORLD listed. The first
  made every anim-input recording attempt fault (`page fault ... at 0x401E4C`, a chunk reached from 0x69D986
  during that program) with `SA_HOOK_PORTS=orig`, because "orig" mode still patches the entry. **This branch
  unregisters all three** (comment at each port; the functions stay ported; STREAM's evidence for them is
  unchanged). 0x7316A0 / 0x7320B0 (`CTxdStore`) are read at +5, outside their 5 patched bytes: unaffected.
  Proposal (harness slot): make sa-hook's installer test reject entries with protection reads.
- **Entries owned by sa-hook's own hooks**: `CPad::Update` (0x541C40) and `CPad::UpdateMouse` (0x53F3C0) are the
  INF-5 input recorder/replayer hooks (group Oracle). Ported, not registered; proposal: the oracle hook chains
  to the port when its toggle is Rust.
- **Not hookable for other reasons**: lone `ret` / `ret N` / `mov; ret` / `xor; ret` entries (too short for the
  5-byte patch); `CAnimManager::Shutdown` (0x4D4130: its loop branches back to 0x4D4133, inside the stolen
  bytes; sa-hook's install test); `CControllerConfigManager::GetJoyButtonJustUp/JustDown` (loop back into their
  own entry bytes).
- **Preserved registers**: the sa-hook `callers` test (ECX/EDX read after a direct call into a hooked entry)
  finds none for these 379 hooks.
- **Port bugs found by the in-game runs (fixed)**: `CCutsceneMgr::UpdateCutsceneObjectBoundingBox` stored the
  larger radius (gta-reversed's reading); the bytes keep the SMALLER of the grown radius and the start radius
  clamped to ≥ 20 (`fld r; fcom slot; test ah,0x41; jne keep` at 0x5B0230) — found by the all-Rust grove-walk
  run (pools/world diverged at frame 275), bisected to this hook in 7 runs. `IKChainManager_c::Update` advanced
  `CWorld::ms_nCurrentScanCode` once per call; the bytes advance it once per slot (the `jl 0x6186E2` loop
  back goes to the scan-code compare: four times per call) — found by L2 (global 0xB7CD78 orig 0x4A, Rust
  0x47), not visible in the 17 trace subsystems.
- **Original bugs kept** (selection; per-row details in the table): `CKeyboardState::Clear` never clears
  `enter`; `MeleeAttackJustDown` tests Square held (no edge); `UpdateMouse` stores buttons as `& 0x80`, writes
  the wheel float and continues after `diMouseInit`; `ProcessPad` keeps the stick axes in PsGlobal (the invert
  is written back), uses `padNumber != 0` for the 2nd/3rd event and returns 0; `StartShake_Distance` sums
  z, y, x; `InitialiseControllerActionNameArray` leaves slots 28/53/58 and writes 45 twice;
  `StoreMouseButtonState` ignores values outside 1..7; `UpdateJoyInConfigMenus_*` write Start only for pad 1;
  `InitDefaultControlConfigMouse` never clears `m_MouseFoundInitSet`; driving steering keys do not test the
  opposite key; `AffectPadFromKeyBoard`'s key-up order; vanilla default keys `'\\'`, `'#'`; the
  `CAnimBlendHierarchy` ctor leaves the hash, sequence `SetName` leaves the flags, `SetNumFrames` only ORs flag
  bits; `MoveMemory` and `NextKeyFrameNoCalc` keep their (gta-reversed: "unreachable") bodies; `SetCurrentTime`
  never returns for a looped animation of total time 0; `QuatToEuler` exact ±1 gimbal tests with f32
  temporaries; `Limit` min-then-max order and the 0.022222223f multiply; `ClampLimitsDefault` / `InitLimits` /
  `SetupBones` read entry −1 (the 0x28 bytes before `ms_boneInfos`) for unknown tags; `EulerToQuat` divides by
  |q|² (no sqrt); `CVehicleAnimGroup::GetGroup` `_ftol(pow(2, bit))` mask (ids ≥ 32 → first group);
  `ComputeAnimDoorOffsets` uses door > 6 as the anim id; cutscene loaders write `gString`.
- **Not reproduced** (stack only, not observable after return): stores into the function's own argument slots
  (`CAnimBlendNode::Update`/`UpdateCompressed` blend factor and fraction, `CPedIK::MoveLimb` (normalized) yaw
  slot, `RotateTorsoForArm` target slot, `CalculateBoundingSphereRadiusCB` atomic slot,
  `UpdateCutsceneObjectBoundingBox` model slot, `SaveSettings`/`LoadSettings` index/version slot; L2 compared
  the argument words of the called ones without a mismatch, i.e. the harness does not see them); SEH frames of
  constructors / `CreateAssociations` / `AddAnimation` / `BlendAnimation`. Original UB: `ReinitControls`
  passes 0 instead of stack garbage as `dwButtons` when `GetCapabilities` fails; `MoveBonesToTarget`'s inverse
  quaternion is 0 (not stack garbage) when |q|² ≤ 0; `CalcWldMat`'s local matrix padding = 0;
  `ComputeCriticalBlendTime(377)` jumps to address 0 in the original, the port panics.
- **Catalogue gaps found**: 0x509840 (`ShockButtonL` "pressed") and 0x53ED90 (`RightStickY` "pressed"), tail
  targets of `HornJustDown` / `GetAccelerateJustDown`, and 0x4CFA90 / 0x4CFB10 (FixedQuat / int16 vector
  decompression, callers in `CAnimBlendNode`) are not catalogue rows (CAT-12); the ports inline them / port
  them unhooked. A protection chunk of `InitDefaultControlConfiguration` (0x409ABF) builds the GO_FORWARD key
  from `[0x15608DC] + [0x5DF174] + 1`; 0x5DF174 is inside `CPed::RemoveGogglesModel`'s entry (0x5DF170): a later
  PED port must not hook that entry (the port reads both dwords at run time like the original).
- **CRT calls**: `pow` (0x8220F0, cdecl entry of `_CIpow`), `acos` (0x822394, cdecl entry of `_CIacos`), `_ftol`,
  `_stricmp`, `sprintf`, `atexit`, the eh vector iterators go through `orig!` (phase A exact).
  `CAnimBlendNode::CalcTheta` models `_CIacos` with `sa_math::x87` (53-bit FPATAN/FSIN; ledger).
- **Globals**: declared with `globals!` where the class owns them (pad statics and mouse states, `ms_boneInfos`
  with the 0x28 bytes before it, bone/IK managers, vehicle anim groups, cutscene associations, `CAnimManager`

  through `g()`.
